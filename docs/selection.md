# Отбор навыков

Набор рассчитан на обычную работу с кодом, без привязки к стеку. «Лучшие» здесь означает наиболее подходящие к повторяющимся потерям: лишнее чтение, догадки при отладке, непроверенная готовность, повторный сбор контекста и дублирование работы агентов. Это критерии отбора, а не опубликованный рейтинг производительности.

| Потеря | Навык | Проверяемая гипотеза |
| --- | --- | --- |
| Чтение всей репы | `context-scout` | Меньше нерелевантного контекста при сохранении верной карты зависимостей |
| Спекулятивные исправления | `debug-issue` | Меньше повторных попыток, воспроизведение действительно устранено |
| Повторение дорогих проверок | `verify-change` | Достаточная проверка без пропуска обязательных тестов |
| Шумное ревью | `review-changes` | Больше подтверждённых дефектов, меньше ложных замечаний |
| Дублирование между агентами | `coordinate-work` | Независимые результаты, отсутствие конфликтов владельцев |
| Восстановление длинной истории | `session-handoff` | Следующая сессия продолжает работу без потери требований |

OpenAI рекомендует пересматривать накопленные инструкции: слишком много навыков и длинные описания затрудняют выбор, а чрезмерно жёсткие рецепты могут мешать сильным моделям. Поэтому в основе короткие инструкции и узкие условия применения. [Rethinking skills and prompts](https://learn.chatgpt.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra).

## Популярные готовые навыки

Из [Superpowers](https://github.com/obra/superpowers) стоит оценить `systematic-debugging`, `verification-before-completion`, `dispatching-parallel-agents`, `using-git-worktrees` и `subagent-driven-development`. Последний включает дополнительные этапы ревью и имеет более высокие затраты на координацию. `executing-plans` предлагается самим проектом как более дешёвый путь выполнения в одном контексте. Полный пакет задаёт обязательную методологию; это существенный выбор поведения, а не только добавление справки.

Для Codex есть также [oh-my-codex](https://github.com/Yeachan-Heo/oh-my-codex) с командными workflow, ролями и HUD. Его стоит оценивать как отдельный runtime поверх Codex CLI. Подробности совместимости — в [каталоге](tools.md).

Встроенные `skill-creator` и `openai-docs`, если они доступны в установленном клиенте, полезны для создания навыков и сверки документации. Их повторные копии не нужны. Специализированные навыки для браузера, GitHub CI и конкретного стека добавляй по возникающим задачам из [официального каталога OpenAI](https://github.com/openai/skills).

## Расширение

Создай `.agents/skills/<имя>/SKILL.md` с коротким описанием применимости и необходимыми инструкциями. Для этой репы frontmatter содержит `name` и одну строку `description` в двойных кавычках. Дополнительные материалы добавляй, когда они действительно нужны процессу. См. [формат навыков](https://learn.chatgpt.com/docs/build-skills).

Проверь явный вызов, естественный запрос и похожий запрос, для которого навык не нужен. Затем сравни задачи с включённым навыком и без него по [методике](../evals/README.md). Сохраняй источник и лицензию при переносе чужого кода или текста. В этой репе сторонние пакеты представлены ссылками и рецептами, без скопированных реализаций.
