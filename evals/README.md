# Проверить экономию и качество

Сейчас сравнительных результатов нет. Проверка структуры навыков и тесты скриптов не являются модельным бенчмарком. Методика основана на [рекомендациях OpenAI по оценке навыков](https://developers.openai.com/blog/eval-skills).

Выбери реальные задачи: поиск пути исполнения, исправление известного бага, ревью diff с известным дефектом, независимые изменения в двух модулях и продолжение работы из handoff. Для каждой заранее запиши ожидаемый результат и проверку, обнаруживающую неверный ответ.

Сравни baseline и candidate на одинаковом исходном commit, с той же моделью, reasoning effort, инструментами, правами и критериями. В baseline убери именно оцениваемые инструкции и роли; сохрани остальные условия. Явный вызов навыка в baseline замени эквивалентной формулировкой задачи. Проверь, что навык не подхватывается из родительской или пользовательской папки.

Используй свежие сессии и одинаковые независимые рабочие копии. Повтори несколько раз и меняй порядок baseline/candidate. Сохрани:

- Прохождение критериев, подтверждённые дефекты и ложные замечания.
- Все input/output tokens, cache hits отдельно, время и повторные попытки.
- Число вызовов инструментов и все дочерние запуски, если они есть.
- Версию Codex, модель, commit набора навыков и условия запуска.

Сначала сравни качество; затем расход успешных запусков. Снижение токенов за счёт пропущенных проверок не считается улучшением. Ускорение параллельной работы и уменьшение суммарных токенов — разные метрики.

## Сохранить JSONL

Запускай следующие команды из тестовой копии с её задачей в `task.txt` и заранее созданной папкой `evals/runs`. Они запускают модель; проверка этой репы их не выполняет.

```bash
codex exec --json - < task.txt > evals/runs/candidate-01.jsonl
python3 /path/to/codex-agents/scripts/report_usage.py evals/runs/candidate-01.jsonl
```

`report_usage.py` читает только события CLI `turn.completed.usage`, суммирует несколько завершённых ходов и отдельно показывает cached input. Это не парсер внутренних rollout-файлов. Результат считается неполным при `error`, `turn.failed` или незавершённом ходе. Суммы относятся только к переданным файлам: полноту учёта дочерних агентов и отсутствие двойного счёта нужно проверить для используемого runtime.

Cached input входит в input; total = input + output. Из этих чисел нельзя вывести денежную стоимость без тарифов модели и нельзя вывести качество без проверок результата. Не включай один и тот же запуск дважды.

## Проверить выбор навыка

| Навык | Должен применяться | Не должен требоваться |
| --- | --- | --- |
| context-scout | «Найди путь от endpoint до записи в БД» | «Замени слово в известном README» |
| debug-issue | «Воспроизведи и исправь падение теста» | «Объясни синтаксис Python» |
| verify-change | «Проверь, что этот patch исправляет регрессию» | «Придумай имя переменной» |
| review-changes | «Проверь diff относительно main» | «Реализуй новую функцию» |
| coordinate-work | «Раздай независимые изменения подагентам» | «Исправь одну опечатку» |
| session-handoff | «Передай эту задачу в новую сессию» | «Продолжай текущую реализацию» |

Это сценарии для ручной оценки триггеров, не выполненные автоматические тесты поведения модели.
